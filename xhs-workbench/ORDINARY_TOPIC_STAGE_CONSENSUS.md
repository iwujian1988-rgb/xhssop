# 普通模式：选题阶段共识存档

更新时间：2026-08-21

## 1. 适用范围

本次共识只针对**普通模式**。

知识库介绍模式不改，不把本文件的规则套到知识库介绍模式，避免两条链路互相污染。

普通模式的主链路是：

```text
用户选择一个封面
-> AI生成3个不同方向的选题
-> 用户选择1个选题
-> 后续正文、内页、标题、标签围绕这个选题生成
```

3个选题是同一个封面下的3种内容方向，不是3个封面，也不是最终生成3篇笔记。

## 2. 选题阶段的作用

选题阶段只负责回答：

> 这篇笔记具体要讲什么，为什么这个用户会想看？

选题阶段不负责：

- 生成最终文字标题
- 生成最终封面标题
- 写正文
- 写内页
- 逐条拼接知识库原文
- 把封面形式直接当成文章主题

选题的核心关系是：

```text
用户真实状态 -> 具体选题 -> 封面是否能承载
```

## 3. 运行时只使用5类入参

每次选题调用不发送整套知识库原文，只发送压缩后的必要信息。

### 3.1 商品身份与商品能力

商品身份回答“卖的是什么”，商品能力回答“这个商品能支持用户做到什么”。

示例：

```json
{
  "商品身份": {
    "商品名称": "DELF B2写作知识库",
    "所属领域": "法语学习 / DELF B2考试 / 法语写作",
    "商品能力": [
      {
        "能力编号": "ability_path",
        "能力": "提供DELF B2写作准备路径",
        "支持模块": ["使用说明与学习路径", "考前冲刺速查"]
      },
      {
        "能力编号": "ability_task_structure",
        "能力": "帮助理解不同写作任务的组织方式",
        "支持模块": ["范文库", "DELF B2评分对照"]
      },
      {
        "能力编号": "ability_transfer",
        "能力": "帮助把范文中的表达、词汇、句法和观点用于新题",
        "支持模块": ["范文库", "词汇库", "句法库", "主题观点库", "组合示例库"]
      },
      {
        "能力编号": "ability_self_check",
        "能力": "提供作文自查的方法和对照维度",
        "支持模块": ["DELF B2评分对照", "错题对照库", "写作检查清单"]
      },
      {
        "能力编号": "ability_review",
        "能力": "提供考前快速定位复习重点的速查资料",
        "支持模块": ["考前冲刺速查", "写作检查清单"]
      }
    ]
  }
}
```

重要口径：

- `商品包含` 是商品客观有什么。
- `商品能力` 是这些内容能够支持用户做什么。
- `支持模块` 是能力的来源锚点，不是让AI自由补充的模块名。
- `能力`不能写成“保证提分”“保证通过”“让用户直接写出高分作文”。
- `支持模块`应由本地商品资料提前整理并确认，运行时只读取，不让AI猜。

### 3.2 购买者地图摘要

购买者地图回答“谁在什么状态下，为什么愿意寻找解决方案”。

```json
{
  "购买者地图": {
    "用户阶段": [
      "正在准备DELF B2写作",
      "已经开始练习写作",
      "距离考试约1到3个月",
      "考前需要集中复习和查漏"
    ],
    "真实状态": [
      "文章能写完，但不知道是否达到B2要求",
      "背过范文，换题后还是不会展开",
      "有观点，但写出来像简单罗列",
      "知道一些词汇和语法，却不会放进文章",
      "写完作文后不知道按什么顺序检查",
      "考前想复习，但不知道先看什么"
    ],
    "购买动机": [
      "不想继续自己摸索和试错",
      "想少花时间整理资料",
      "想快速找到能直接练习的内容",
      "想把范文、句型、观点和检查方法放在一起",
      "想降低临近考试时的不确定感"
    ]
  }
}
```

区分方式：

```text
用户阶段：用户处于哪个备考阶段
真实状态：用户现在具体哪里难受
购买动机：用户为什么愿意寻找甚至购买解决方案
商品能力：商品实际上能提供什么支持
```

语义相近不等于重复。例如：

```text
真实状态：不知道考前先复习什么
购买动机：想在有限时间里快速找到重点
商品能力：提供考前快速定位复习重点的速查资料
```

这三者是“问题 -> 动机 -> 商品承接”的关系。

### 3.3 当前封面能力

封面信息由系统根据用户选择的模板自动提供，用户不需要自己判断排版限制。

封面不是决定文章主题的东西，而是决定内容最后如何展示。

羊皮纸资料目录型示例：

```json
{
  "当前封面": {
    "封面名称": "羊皮纸资料目录型",
    "封面作用": "把内容展示成一页整理好的资料体系",
    "适合承载": ["知识体系", "清单", "备考路径", "多个分类", "考前速查"],
    "内容形态": "多个分组，每组包含若干短条目",
    "信息密度": "中高",
    "不适合承载": ["长故事", "纯个人经历", "大段情绪表达"]
  }
}
```

大字痛点型示例：

```json
{
  "当前封面": {
    "封面名称": "大字痛点型",
    "封面作用": "用一句话让用户第一眼感到与自己有关",
    "适合承载": ["一个明显痛点", "一个反常识观点", "一个结果或提醒"],
    "内容形态": "一句主标题，可配一句副标题",
    "信息密度": "低到中",
    "不适合承载": ["完整目录", "多组知识清单", "长篇解释"]
  }
}
```

封面限制是系统预设的模板能力，不是让AI现场猜测的要求。

### 3.4 历史去重信息

```json
{
  "历史去重信息": {
    "最近使用过的选题": [],
    "最近使用过的标题": [],
    "最近使用过的表达方向": []
  }
}
```

历史记录用于避免连续重复，不要求AI避开所有相近主题。

至少避免：

- 同一选题重复
- 同一角度重复
- 同一标题只换几个字
- 连续使用同一种情绪和开头

### 3.5 本次生成要求

```json
{
  "本次生成要求": {
    "选题数量": 3,
    "选题方向": ["大痛点型", "省时路径型", "具体方法型"],
    "用户是否选择": true,
    "生成语言": "中文"
  }
}
```

这里把“捷径结果型”正式改名为“省时路径型”。

保留的不是“短期考试结果承诺”，而是：

- 少花时间整理
- 少走弯路
- 更快理清重点
- 知道先做什么、后做什么
- 缩小复习范围

禁止暗示短期学习可以替代持续练习，也不能承诺一定提分或一定通过。

## 4. 选题阶段完整入参

实际运行时传入的对象由以上5块组成：

```json
{
  "商品身份": "商品身份与商品能力摘要",
  "购买者地图": "用户阶段、真实状态、购买动机摘要",
  "当前封面": "系统生成的封面作用和承载形态",
  "历史去重信息": "最近选题、标题和表达方向",
  "本次生成要求": "固定生成3个方向"
}
```

不传：

- 全部Markdown原文
- 全部事实卡
- 全部标题库
- 全部竞品图片OCR
- 详细CSS代码
- 后续正文的完整提示词

这样可以减少token，也避免选题AI被无关信息稀释注意力。

## 5. 选题生成方向

### 5.1 大痛点型

找用户正在经历的、值得马上解决的问题。

不能只写“写作很难”，要写清楚用户具体哪里不舒服，例如：

- 文章能写完，但不知道是否达到B2要求
- 背过范文，换题后还是不会展开
- 写完作文后不知道先检查什么

### 5.2 省时路径型

围绕用户不想继续自己整理和试错，想更快找到当前重点、明确先后顺序的需求，设计一个能说明“先做什么、后做什么”或“如何缩小复习范围”的选题。

不能承诺一定提分、一定通过，不能暗示短期学习可以替代平时练习。

### 5.3 具体方法型

选择一个可以实际讲清楚的方法、顺序、检查方式或练习方式，必须能展开成3到5个具体内容。

例如：

- 从观点到解释、例子和让步，如何把段落展开
- 写完作文后，按什么顺序进行检查
- 范文中的句型如何迁移到新题

## 6. 选题系统提示词

```text
你是资深小红书法语备考内容策划。

你的任务不是介绍商品目录，也不是直接写正文，
而是根据商品能力、购买者真实状态和当前封面形式，
提出3个值得用户点击和继续阅读的内容选题。

请遵守以下规则：

1. 选题必须属于当前商品所属领域。
2. 选题必须让目标用户看出“这和我有关”。
3. 选题必须对应一个真实备考场景。
4. 选题必须有具体内容可以展开。
5. 选题必须能自然使用当前封面的内容形态。
6. 当前封面只决定内容如何展示，不决定文章必须讲什么。
7. 不要把商品模块名称直接当成选题。
8. 不要把抽象口号当成选题。
9. 不要使用“资料太散、卡住、拖后腿、正在白背”等机械化表达。
10. 不要把过于细小的知识点包装成所有用户都会遇到的大痛点。
11. 3个选题必须分别解决不同层次的需求，不能只是换几个词。
12. 普通模式允许AI原创解释、方法和例子，不要求每个选题都命中某个事实卡。
13. 但不能把商品没有的服务、资历或功能写成商品内容。
14. 如果涉及DELF B2的具体考试规则、评分标准、题型要求、字数要求、格式要求、官方规定或商品实际包含内容，只能使用输入中明确提供的信息，不得自行编造、夸大或包装为确定事实。
15. 如果只是一般性的学习方法、练习建议或表达示例，可以由AI原创，但不能包装成官方规定或确定事实。
16. 不生成最终文字标题，不生成最终封面标题，不生成正文。
17. 只输出选题策划结果。
```

## 8. 选题出参

固定返回3个选题，不是6个，也不是根据封面数量返回。

```json
{
  "选题列表": [
    {
      "选题方向": "大痛点型",
      "选题名称": "写完作文后不知道怎么自查",
      "对应的用户真实状态": "文章写完了，但不知道哪里不符合B2要求",
      "用户使用场景": "考前练完一篇作文，改了几遍还是不放心",
      "用户真正想得到的结果": "有一套明确的检查顺序",

      "准备展开的内容": [
        "检查是否完成题目要求",
        "检查文章结构是否完整",
        "检查观点和例子是否对应",
        "检查连接表达和句法",
        "检查称呼、格式和字数"
      ],
      "商品承接依据": {
        "商品能力": "提供作文自查的方法和对照维度",
```

`商品承接依据`的作用是让用户看到这个选题不是凭空想出来的；它不是把资料模块直接变成选题，也不是要求正文逐条复制这些模块。

## 9. 选题判断边界

### 直接拒绝

只有以下情况才直接拒绝：

- 把DELF B2写成TEF/TCF，或把写作写成听力、口语
- 选题和所选封面完全无法承载
- 选题没有任何具体内容可以展开
- 3个选题其实是同一句话
- 明显编造商品没有的服务、资历或功能

### 只提醒，不拦截

以下情况不应导致整张任务失败：

- 用户痛点表达不够漂亮
- 选题不够爆
- SEO词不够强
- 商品承接不够明显
- 选题偏原创科普
- 没有命中某个事实卡
- AI少返回一个非关键说明字段

普通模式不是：

```text
事实卡找不到 -> 失败
```

而是：

```text
主题成立 -> 允许AI写
商品能自然承接 -> 加分
商品完全不相关 -> 提醒或换选题
```

## 10. 用户选择后锁定

用户选择一个选题后，系统保存：

```json
{
  "已确定选题": {
    "选题方向": "具体方法型",
    "选题名称": "有观点但不会把文章写展开",
    "核心问题": "观点无法扩展成完整段落",
    "内容承诺": "展示观点、解释、例子和让步的展开方法",
    "准备展开的内容": [
      "观点",
      "解释",
      "例子",
      "让步",
      "收束"
    ],
    "商品承接依据": {
      "商品能力": "帮助把观点、词汇和句法迁移到新题",
      "支持模块": ["主题观点库", "组合示例库", "句法库"]
    },
    "已锁定": true
  }
}
```

从此以后，正文、内页、标题和标签都读取这份已锁定选题，不允许中途换方向。

## 11. 最终共识

```text
商品信息：卖的是什么
购买者地图：用户为什么需要
封面信息：最后怎么展示
选题：这篇具体讲什么
```

运行时不增加新的AI节点：

```text
已确认的商品/用户基础资料
-> AI生成3个选题
-> 用户选择1个
```

商品能力与支持模块的对应关系需要提前确认；普通模式允许AI原创一般学习方法、解释和例子，但涉及具体考试规则、评分、题型、字数、格式、官方要求和商品实际内容时，只能使用输入中明确提供的信息。

本文件最初只存档普通模式的选题阶段共识。以下补充已经确认的后半段设计共识；这些内容仍是设计存档，暂不代表代码已经完成改造。

## 12. 选题之后的普通模式流程

```text
用户选定封面
-> AI生成3个选题
-> 用户选择1个
-> 锁定主题
-> 生成内容任务单
-> 生成正文和内页内容
-> 单独生成文字标题和封面标题
-> 使用已选封面模板排版
-> 生成标签
-> 最终检查
```

### 12.1 标题节点的位置

标题节点放在正文和内页内容之后。它不直接把选题名称改几个字，而是读取：

- 已锁定选题
- 正文
- 内页摘要
- 商品信息与购买者地图
- 当前封面模板的视觉形式和容量
- 历史标题去重信息

一次生成两类候选：

- 文字标题：负责笔记点击，允许更完整地表达用户场景、情绪和收益。
- 封面标题：负责缩略图第一眼建立关系，必须更短、更醒目、更容易看清。

标题风格必须符合以下共识：

- 第一眼看出与法语、DELF B2或本篇具体学习场景有关。
- 让用户感到“这说的就是我”，不能只写抽象知识名称。
- 可以使用后悔、惊讶、焦虑缓解、反常识、少走弯路、捷径感和分享欲。
- 资料型标题突出数量、时间、完整度、时效性、实用价值或收藏价值。
- 不固定套用“XXX？先XXX”的句式。
- 不使用用户难以理解的表达，例如“资料太散”“写作任务”“格式正在拖后腿”。
- 不把标题写成教材目录或AI说明书。
- 允许使用强带货词，但正文和内页必须能证明其具体价值。

标题节点只负责产出候选和筛选，不负责改变选题，也不负责重新决定正文内容。

### 12.2 标题的最低输出结构

```json
{
  "文字标题候选": [
    {
      "标题": "...",
      "方向": "资料型/痛点型/情绪型/反常识型/结果型/陈述型",
      "对应正文依据": "..."
    }
  ],
  "封面标题候选": [
    {
      "标题": "...",
      "方向": "...",
      "对应内容依据": "...",
      "适合当前封面": true
    }
  ]
}
```

标题数量由前台任务配置决定，不由提示词写死为某个固定数字。若当前任务要求每类各给候选，就必须由程序把数量传给AI；AI少返回时只能补标题候选或降级，不应让整篇任务失败。

### 12.3 标题节点的提示词原则

AI必须被明确要求：像真实小红书用户说话，有具体场景和反应，有点击理由，同时保留必要搜索词。不能只做关键词拼接，不能把所有标题写成同一种问句结构，也不能把选题标题直接当成成品标题。

AI还必须检查：标题是否被正文前两段和内页真正接住；若接不住，只改标题，不重跑整篇内容。

## 13. 标题、内页和封面模板能否匹配

可以匹配，但三个概念要分开：

```text
选题决定：这篇内容讲什么
内容任务单决定：正文和内页讲哪些部分
标题节点决定：用什么话把用户吸引进来
封面模板决定：这些文字如何被视觉呈现
```

标题节点不能凭空决定内页页面，也不能让封面模板反过来改变选题。正确做法是：

1. 用户先选择封面模板，系统把模板的视觉形式、容量和适合承载的内容形态传给选题节点。
2. AI生成选题时就知道该封面适合表现什么内容，但封面只提供边界，不强行规定选题。
3. 选题确定后，内容任务单根据选题规划正文和内页页面。
4. 标题生成时读取已经确定的正文和内页摘要，保证标题不是空喊口号。
5. 封面排版时只使用已选封面模板和最终封面标题，不重新创作主题。

因此，封面样式的匹配不是靠标题节点临时猜，而是靠两层信息共同完成：

- 选题阶段读取封面模板的承载能力，避免选题完全无法展示。
- 排版阶段读取封面模板的容量规则，处理行数、字号、位置和遮挡。

如果用户选择的是羊皮纸目录型封面，内容任务单应优先组织成可分组、可列举、可快速查阅的内容；如果用户选择的是情绪大字报，内容可以是一个具体痛点或反应，不能强行塞成知识目录。若封面承载能力不足，优先缩短封面标题或调整内容展示，不改变已经锁定的选题。

## 14. 后半段的拦截原则

后续质量问题不得全部变成任务失败。

- 硬拦截：完全跑题、明显错误的法语例句或释义、虚构商品服务、封面渲染失败、文字被遮挡且无法恢复。
- 局部返修：标题不够好只返修标题，内页太密只返修内页，商品承接弱只返修承接段。
- 提醒放行：情绪不够强、SEO偏弱、资料依据没有完全命中、风格不够网感、购买理由偏弱。

事实依据是软约束。普通模式找不到完全对应的事实时，允许AI原创一般解释、方法和例子，但不能把原创内容包装成官方考试规定，也不能说商品明确包含不存在的内容。

## 16. 最终标题优化节点共识

标题优化节点位于正文和内页生成之后、封面排版之前：

```text
正文/内页完成
-> 读取旧标题草稿
-> 生成多方向标题
-> 人话改写
-> 字数/重复/跑题检查
-> 输出文字标题和封面标题
-> 进入封面排版
```

### 16.1 节点职责

这个节点不是第一次生成选题，也不是把选题标题原样改几个字。它要把选题阶段和前面已有的标题草稿，结合最终正文、内页、商品信息、购买者地图和封面容量，重新优化成可以发布的小红书标题。

它必须同时输出两类标题：

- `文字标题`：负责让用户点击笔记，可以更完整地表达场景、情绪、问题和收益。
- `封面标题`：负责缩略图第一眼建立用户关系，必须更短、更醒目，适合当前封面容量。

旧标题是草稿和参考，不是必须保留的内容。旧标题平淡、不说人话、没有点击欲或与正文不一致时，AI可以直接重写。

### 16.2 标题节点入参

```json
{
  "商品信息": "当前商品的名称、领域、能力和商品模块",
  "购买者地图": "当前商品的用户阶段、真实状态和购买动机",
  "已确定选题": "选题方向、主题、用户问题、核心内容和商品承接方向",
  "已有标题草稿": {
    "选题标题": [],
    "文字标题": [],
    "封面标题": []
  },
  "正文": "最终正文内容",
  "内页摘要": "每个内页的标题和核心内容",
  "当前封面": {
    "模板ID": "...",
    "视觉形式": "...",
    "适合承载": [],
    "排版容量": {}
  },
  "搜索词": "当前商品的搜索词池",
  "历史标题": "当前商品已经使用过的标题",
  "生成要求": {
    "标题组数": "由任务配置传入",
    "文字标题上限": 20,
    "封面标题上限": "由封面模板传入"
  }
}
```

标题节点不能只接收选题标题。只接收选题标题会让AI容易输出平淡的选题改写；正文和内页摘要是判断标题是否有真实内容支撑的必要输入。

### 16.3 标题方向

标题方向是内部创作方向，不是固定句式。每次应拉开不同方向，不能所有标题都写成同一种“问题+解决方法”结构。

- 资料/大全型：数量、时间、完整度、时效性、实用价值、收藏价值。
- 大痛点型：用户正在经历的具体问题。
- 情绪型：后悔、意外发现、焦虑缓解、松一口气、强烈推荐或分享欲。
- 反常识型：指出常见但不一定有效的准备方式。
- 结果/省时路径型：少走弯路、快速定位重点、知道先做什么，但不保证考试结果。
- 真人陈述型：像用户在讲自己的整理、发现或使用感受。

标题必须让用户第一眼知道和当前法语考试/学习场景有关，并产生“这和我有关”“我正需要这个”或“这个值得点开看看”的理由。允许有网感和带货力度，但不能凭空创造痛点、商品功能、考试规则、官方身份、用户结果或反馈。

```json
{
  "标题优化结果": {
    "推荐组": 1,
    "候选组": [
      {
        "组号": 1,
        "方向": "资料/大全型",
        "文字标题": "...",
        "封面标题": "...",
        "文字标题字数": 0,
        "封面标题字数": 0,
        "标题依据": {
          "选题依据": "...",
          "正文依据": "...",
          "内页依据": "...",
          "商品依据": "..."
        },
        "适合当前封面": true,
        "需要人工注意": ""
      }
    ],
    "淘汰标题": [],
    "提醒": []
  }

```

标题组数由任务配置决定，不在提示词里写死。每组标题必须配对：一条文字标题对应一条封面标题，不能出现标题数量不一致或封面标题来自另一条内容的情况。

### 16.5 标题提示词的核心要求

```text
你是一名资深小红书编辑，负责把已有内容改写成真正能发布的标题。

不要重新设计选题，不要改变正文主题。已有标题只是草稿，如果平淡、不说人话、没有点击欲或没有被正文接住，可以直接重写。

标题要像真实用户看到一个有用资料后，忍不住想分享给同类人的一句话，而不是课程目录、论文标题、知识库字段、AI总结或关键词广告。

第一眼要让目标用户知道这和当前法语考试/学习场景有关，并感到这与自己的阶段、问题或备考动机有关。

资料型标题要突出数量、时间、完整度、实用价值或收藏价值；痛点型标题要使用真实用户状态；情绪型标题要有真实反应；反常识型标题要指出常见误区；省时路径型标题要强调少整理、少试错和快速找到重点。

不要把所有标题写成同一种问句结构，不要堆关键词，不要使用用户日常不会说的抽象痛点，也不要为了追求爆款凭空增加考试事实、商品功能、用户反馈或考试结果。

文字标题负责点击，封面标题负责缩略图第一眼建立用户关系。封面标题必须短、醒目并适合当前模板容量，不能把完整文字标题压缩到看不清。

每条标题都必须能在选题、正文、内页或商品信息中找到依据。输出的标题要有明显方向差异，并避免与当前商品历史标题使用相同的开头、后半句或句式。
```

### 16.6 标题问题的处理级别

- 超过平台字数、完全跑题、与历史标题高度重复、标题虚构商品内容：淘汰或局部返修。
- 标题不够有情绪、不够网感、SEO偏弱、带货承接偏弱：提醒，不让整篇任务失败。
- 标题和正文主题不同：只返修标题，不重跑正文和内页。
- 封面标题超出模板容量：优先局部缩短或重新生成封面标题，不缩小到无法阅读。
